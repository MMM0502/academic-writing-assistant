# 产品需求与架构

## 1. 用户与场景

目标用户为本科生、研究生和指导教师。核心场景是：用户正在准备课程论文、毕业论文或项目报告，面对格式不统一、参考文献手工整理耗时、多篇文献难以形成研究脉络等问题，希望在浏览器中完成一次上传和初步处理。

## 2. MVP 范围

### Epic A：文稿范式规整

1. 用户上传单篇 Word/PDF/TXT 文稿。
2. 系统提取正文和参考文献。
3. 用户选择 GB/T 7714、APA 7 或 IEEE。
4. 系统统一编号与格式。
5. 系统提示重复引用、缺失年份等风险。
6. 用户查看结果并下载 Markdown。

### Epic B：文献综述生成

1. 用户输入研究主题。
2. 用户批量上传文献。
3. 系统提取标题、年份和关键词。
4. 系统聚合研究主题。
5. 系统生成研究概述。
6. 系统生成主题脉络。
7. 系统生成研究不足与展望。
8. 用户查看来源与生成引擎。
9. 用户下载综述 Markdown。

### Epic C：工作区管理

1. 系统保存处理记录。
2. 用户查看历史记录。
3. 用户从历史记录下载结果。
4. 系统提供健康检查接口。
5. 系统提供错误提示与可恢复的本地规则回退。

## 3. 非功能需求

- 可用性：首次打开不需要注册和密钥；错误以中文展示；核心流程不超过三步。
- 安全性：限制单文件 12 MB；文件名只保留安全字符；不执行上传文件；默认只绑定本机地址；历史数据仅保存处理结果。
- 可维护性：解析、格式化、综述、存储和 HTTP 层分离；规则引擎可替换为大模型适配器。
- 可靠性：大模型调用失败自动回退到本地规则引擎；历史记录使用 SQLite 持久化。

## 4. 架构

浏览器前端 -> Python 标准库 HTTP API -> 解析器 / 格式化器 / 综述引擎 -> SQLite。

大模型增强路径为可选外部依赖，不作为 MVP 的启动前置条件。
